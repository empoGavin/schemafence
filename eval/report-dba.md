## 5. 三行结论（必须自己写，不许留空）

1. 最好的一组是：**512 tokens / overlap 64**（当前默认），依据是它在本语料上命中 97.4%
   （37/38）、切片数 35、平均 304 tokens，既没有把段落切碎（256 会切断"排序依据"那类小标题段），
   也没有把多个主题糊成一片（1024 会让一个切片同时讲三件事，稀释相关性）。
2. 语料或切片上最大的意外是：**失效样本一律是"词形问题"，不是"切片问题"。**
   两次失效（"一半 vs 50%"、"spin lock vs s_lock"）都在三种切片尺寸下同样失效，
   说明量的是同一个根因：离线哈希词袋只看字面重合，**"代码写法"和"口语写法"必须在语料里各出现一次**。
   第二次失效直接推动了一条语料改进（把 `_raw_spin_lock` / `native_queued_spin_lock_slowpath` 补进 perf 符号清单），
   补完立刻变成 rank-1——这就是"题库当量尺"的实际收益。
3. 下一轮要改的一件事是：**接上 API 嵌入（`SF_LLM_API_KEY`）跑同一份 38 题**，
   用"磁盘/一半"这道同义词题量化词法 vs 语义的差距；如果语义模式把它拉回 rank-1，
   就把这次对比数据写进简历与面试话术（"我知道离线词法嵌入的失效边界在哪，并且量过"）。
