## 5. 三行结论（必须自己写，不许留空）

1. 最好的一组是：512 / 64 / top-5（默认，97.7%，43/44）。剩下那一分是纯词形问题
   （"一半" vs "50%"），top-10 也救不回来，说明提 k 换不来它，得换嵌入。这里要分清两件事：
   top-5 → top-10 提的是覆盖率（顺带兜住排序问题），换嵌入才是提检索质量。
   `1024 / 128 / 10` 的 2.4 ms 看着最漂亮，但片数只剩 24：一个切片同时讲三件事，
   命中率高是因为整篇被糊成一片，在主题少的小语料上会系统性高估，不要抄这一行。
2. 语料或切片上最大的意外是：**扩语料先暴露的是标注，不是检索。** 14 篇里已经有 3 对相邻主题
   （膨胀治理 / 膨胀误诊、连接池 / idle 事务、子事务 / 长事务），新增笔记一进来就和老笔记抢同一道题。
   44 题在单来源标注下只有 95.5%，允许一题多来源之后回到 97.7%——丢的 2 分里，1 分是真实的检索失败
   （词形问题），另 1 分是标注造成的假失败。
   失效那一分与切片尺寸无关（256/512/1024 结果一样），根因是离线哈希词袋只看字面重合，
   所以语料里"代码写法"和"口语写法"必须各出现一次。
   顺带一个正面结果：语料涨到 40 片之后，调参表终于有了区分度（93.2% / 95.5% / 97.7%），
   在此之前 27 组全部打平——"小语料上所有配置都并列第一"这句话，现在有数了。
3. 下一轮要改的一件事是：接上 API 嵌入（`SF_EMBED_API_KEY`）跑同一份 44 题，
   用"磁盘/一半"这道同义词题量化词法 vs 语义的差距。顺带一个用途：`--eval` 现在会打印
   每题 top-1 分数，本轮命中题的最低 top-1 是 0.089（离线模式）。离线分数低到不能设绝对
   相关度地板（`SF_DOC_MIN_SCORE` 只能留 0），必须等 API 嵌入进到 0.5–0.7 区间，那个地板才有标定意义。
   这组对比值得保留：离线词法嵌入的失效边界在哪，是可以量出来的。
