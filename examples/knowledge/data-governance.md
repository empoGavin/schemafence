# 数据治理与生命周期管理

## 治理解决的是什么问题

不是"把数据管起来"，而是回答三个问题：**哪些数据还在被用、哪些可以降级、哪些必须留痕**。
没有这三个答案，所谓治理就会变成一场加字段、加标签的运动。

## 从 104TB 压到 20TB 的四类动作

1. **冷热识别**：按访问时间与业务属性把数据分成热、温、冷三档。这一步全靠日志与业务访谈，
   不能靠猜
2. **归档而非删除**：冷数据迁到低成本存储，保留可查询入口，满足审计要求
3. **去冗余**：同一份数据被多个系统各存一份是常态。合并副本的收益往往比压缩更大
4. **分区化**：按时间分区之后，"删旧数据"变成 DROP PARTITION，从小时级 IO 操作变成秒级元数据操作

## 治理的副产品

- 数据资产目录：任何一张表都能回答"谁产生、谁使用、保留多久"
- 生命周期策略：写入即定义保留期，而不是等空间不够时再讨论
- 成本可见：每个业务域占用的存储与其收益挂钩

## 判断治理是否真的有效

看两个指标：**单位业务量对应的存储增长斜率**，以及**冷数据的访问率**。
如果压缩之后数据量半年内又涨回去，说明生命周期策略没落地，只做了一次性清理。

## 与 AI 方向的关系

数据治理的成果是一份"数据语义说明书"：每个字段是什么意思、什么情况下会为空、
哪些值代表同一件事。这正好是大模型最容易误读的部分——
给表加注释只能覆盖声明性知识，而"某个状态值实际上已经被废弃"这类知识，
只能来自治理过程。这也是做数据库 AI Agent 时最稀缺的输入。
