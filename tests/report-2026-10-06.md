## 4. Bug 清单

### BUG-1（严重度：中；维度 A / guard）字符串护栏放行三类"带写意图的 SELECT"

**现象**：`SELECT * INTO newtable FROM ...`（等价 CREATE TABLE AS，物化一张表）、`SELECT nextval(...)` / `setval(...)`（推进/设置序列，属写）、`SELECT ... FOR SHARE`（加锁读，只读事务会直接拒绝）在字符串护栏层全部 `ok=True`。三者都不以下列被禁关键字开头，L2 前缀检查与 L3 关键字表都漏过。

**复现（修复前）**：

```bash
python -c "from schemafence.guard import guard; print(guard('SELECT * INTO shop.evil FROM shop.orders').ok)"
# True   ← 应该 False
```

**根因**：`FORBIDDEN_KEYWORDS` 无 `INTO`；`DANGEROUS_FUNCTIONS` 无 `nextval/setval`；L2 未识别行锁子句。

**缓解**：L7 会话 `SET default_transaction_read_only = on` 会在库侧拒绝这些语句——所以这是**纵深防御的缺口**，不是唯一防线被击穿。但护栏自身宣称"L2 只读形态"，就应挡住形态本身。

**修复**：`schemafence/guard.py`——`INTO` 进 L3；`nextval|setval` 进 L4；新增 `WRITE_CLAUSE` 正则，在 L2 拒绝 `FOR [NO KEY|KEY] UPDATE / SHARE`。commit `14b03d2`。

**回归**：`tests/qa_probe.py` A21–A24 由 FAIL 转 PASS；`demo.py` [guard] 13 例仍全绿；随机抽查合法只读查询（A4/A18/A19/A20）未被误杀。

### BUG-2（严重度：中；维度 D / CLI）坏输入抛裸栈回溯，而非一行错误

**现象**：以下四种坏输入都从 `main()` 直接抛异常、打印完整 traceback（退出码 1）：

| 命令 | 异常 |
|---|---|
| `--ingest tests/tmp/no-such-dir` | `FileNotFoundError: no such corpus directory` |
| `--report ... --corpus tests/tmp/no-such-dir` | `FileNotFoundError`（来自 `tune_rows`） |
| `--search-path 'bad;drop'` | `ValueError: --search-path looks wrong` |
| `--mode api`（未设 `SF_EMBED_API_KEY`） | `RuntimeError: mode='api' needs SF_EMBED_API_KEY` |

**复现（修复前）**：

```bash
python agent_cli.py --ingest tests/tmp/no-such-dir --store tests/tmp/x.json
# Traceback (most recent call last): ... FileNotFoundError: no such corpus directory: tests\tmp\nope
```

**根因**：`main()` 内 `make_embedder()` 与各 `cmd_*` 都没有对"输入型异常"做处理；消息本身是清楚的，只是交付方式（栈回溯）不对。相比之下 `--ask` 空 store 已能用"退出 2 + 一行提示"处理，行为不一致。

**修复**：`agent_cli.py`——`make_embedder()` 与命令分派各包一层 `except (FileNotFoundError, ValueError, RuntimeError)`，打印 `error: <msg>` 到 stderr 并返回 2（与既有坏参数路径一致）。故意不捕获 `TypeError` 等编程错误，保留栈回溯。commit `87b60be`。

**回归**：D14–D17 由 FAIL 转 PASS；正常路径（D1–D13、D18）不受影响。

### BUG-3（严重度：低；维度 C / tools）`search_docs(k=0)` 回退到 5，而非夹到下限 1

**现象**：`k = max(1, min(int(k or 5), 20))` 中 `0 or 5` 把显式 `k=0` 当作"缺省"，于是 `max(1, 5) = 5`，下限夹取对唯一想表达"只要一条"的取值从未生效。

**复现（修复前）**：

```bash
python -c "import sys; sys.path.insert(0,'.'); from schemafence.knowledge import Embedder, JsonStore; from schemafence.tools import Toolbox; print(Toolbox(store=JsonStore('tests/tmp/dba.json',1024)).call('search_docs', {'query':'x','k':0}).data['k'])"
# 5   ← 应该 1
```

**根因**：`k or 5` 的 falsy 语义把 `0` 与 `None` 混为一谈。

**修复**：`schemafence/tools.py`——`k = 5 if k is None else max(1, min(int(k), 20))`。commit `b830853`。

**回归**：C7 由 FAIL 转 PASS；C6（k=99→20）仍 PASS；`run_tool_selftest` 7 例全绿。

## 5b. 产物完整性：G5 与它咬住的那个缺陷

G 组复现的是「终端全绿、留下的文件残缺」这一类。`--suite guard` 不需要库、`--suite checks --db` 需要，
所以七层套件天然是两条命令，而两条命令默认共用 `bench/layers.json`——第二条曾把第一条覆盖掉。
合并修复之后还留了一处同源缺陷：`merge_into_existing()` 重算了 `passed`/`failed`/`skipped`，
却没写 `total`，文件里那个字段是 `None`。

**为什么它算缺陷而不是美观问题**：报告脚本走 `suites` 逐条读，所以 `bench-report.md` 的表格一直是完整的；
但任何按 `total` 判断"这一轮跑全了没有"的检查都会读到假阴性——正是这个函数存在的理由在高一层重演。

**修复**：`merge_into_existing()` 补 `"total": len(fresh)`，在合并后的行上重算。commit 见 §7。

**变异验证**：删掉那一行后重跑 `qa_probe.py`，G5 报 `FAIL … total=None rows=62`，79/80。
说明 G5 咬的就是这个缺陷，不是恒真断言。
